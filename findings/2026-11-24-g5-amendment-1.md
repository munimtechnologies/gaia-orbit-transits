## Why

The DR3 screen (`findings/2026-11-23-sb2-screen-results.md`) found three new double-lined eclipsing
binaries with Gaia masses (HD 250735, CD-28 7251, TYC 3616-2395-1). On release day the same screen
runs on Gaia DR4's much larger double-lined orbit list (step g5), so the screen must give a
trustworthy "new" list. On DR3 it did not: its Villanova TESS EB lookup failed on all 56 stars it
was asked about (HTTP 400), the registered rule counted every failure as "not found", and 3 of its
8 "new" stars turned out to be in the TESS EB catalogue.

## What we found today (by hand, 24 Nov ~02:00 UTC)

- **The cause:** the screen asked `http://tessebs.villanova.edu/<TIC>`. The site answers on
  **https**. Through https, TIC 238162238 (HIP 34208, a Prša et al. 2022 binary) shows a signal
  with "In catalog? True" and P = 2.4374384 d. TIC 189269584 (CD-28 7251) shows "No associated EB
  entries found".
- **A prior-art check that had failed now succeeds for all three discoveries.** The live Villanova
  TESS EB catalogue has **no entry** for TIC 189269584 (CD-28 7251; TESS sectors 8, 9, 35, 62),
  TIC 384284045 (TYC 3616-2395-1; sectors 56, 57, 76, 77, 83, 84) or TIC 400170926 (HD 250735;
  sectors 43, 44, 45, 71, 72, 73). Before today only the static VizieR copy (Prša et al. 2022)
  had been checked.
- VizieR's CfA mirror returned "The database is not currently reachable" today, and the CDS
  hosts refused connections from our web reader. So a VizieR lookup can fail at any time, and
  it needs a control row on every run.

## The changes (0.2.0)

1. **Villanova over https**, with a parser that reads the signal table ("In catalog?" then a
   True or False cell). **Controls run before any star:** TIC 238162238 must come back True and
   TIC 189269584 False. If either fails, the lookup is switched off (unknown) for every star.
2. **Two VizieR lookups**, the TESS EB catalogue (J/ApJS/258/16) and the TESS Ten Thousand
   catalogue (J/ApJS/279/50), tried on the CfA mirror and then CDS. Each has a **self-generated
   positive control**: the first row the catalogue returns must be found again by the lookup mode
   we use (a 5″ cone around its own position, otherwise its TIC). A reply that is not VizieR's
   own (an HTML error page) is an error, never "0 rows".
3. **NEW_V2:** a star with a TESS TCE at the Gaia period or half of it is NEW_V2 only if
   all six lookups (VSX, Villanova, SIMBAD, the two VizieR catalogues, ExoFOP TOIs) answered and all
   were negative, and Gaia's own eclipsing tables do not list it. Any lookup that could not answer
   makes the star **UNVETTED** (vetted by hand), never new. The old S2 count is still reported.
4. **DR4 schema gate:** before any query the job reads TAP_SCHEMA. If DR4's double-lined orbit
   table lacks a column the selection needs, it exits with code 4 (gate G0: write an adapter, re-file
   as -v2), as step (i) does. If DR4 has **no binary_masses table**, the registered mass-ratio cut
   cannot be made, and **arm B** runs instead: every SB2 orbit with P < 8 d and G < 11, brightest
   800 first. Arm B has no edge-on cut, so it expects a lower eclipse rate per star.
5. The registered g5 prediction stands, now on NEW_V2: at least 5 new double-lined eclipsing
   binaries with Gaia masses (50%). Every NEW_V2 star is still vetted by hand before it is called
   a discovery (the DR3 list shows why: a heartbeat star and a Kepler KOI would pass this rule).

## Rehearsal on DR3 (job g5-lookup-rehearsal-v1), with predictions fixed now

The job reads the DR3 screen's own output (`data/sb2-edgeon-screen-v1/sb2_screen.csv` at commit
80be2827), so it does not need ESA's archive, which closes on 25 Nov at 12:00 CET. It reruns only
the new lookups on the 56 stars with a TCE at P or P/2 and keeps the old VSX, SIMBAD and TOI answers.

- **R1** Villanova repaired: controls correct and at least 7 of the 8 hand-vetted stars
  (`data/sb2-new-ebs/vetting.csv`, column prsa2022_tess_eb) agree: **LOOKUP_REPAIRED**, otherwise
  LOOKUP_STILL_BROKEN.
- **R2** the NEW_V2 / UNVETTED / KNOWN counts among the 56.
- **R3** share of the 56 × 6 lookup answers that are definite: **LOOKUPS_DEFINITE** if ≥ 0.95,
  otherwise LOOKUPS_GAPS.
- It also records whether TAP_SCHEMA can be read for gaiadr3 and which arm the gate picks
  (expected: A), if ESA's archive is still open when the job runs.

| prediction | probability |
|---|---|
| unit tests and self-test pass | 80% |
| Villanova controls pass | 80% |
| R1 LOOKUP_REPAIRED | 75% |
| at least one VizieR catalogue passes its control | 65% |
| R3 LOOKUPS_DEFINITE | 55% |
| NEW_V2 is exactly HD 144359, CD-28 7251, HD 250735, BD+37 3347 and TYC 3616-2395-1 | 50% |
| none of the three discoveries comes out KNOWN | 90% |

If R1 fails, release day uses hand vetting for Villanova, as on DR3. If a VizieR control fails, those
stars are UNVETTED, not new, which is the point of the change.

## Limits

The rehearsal reuses the DR3 run's VSX, SIMBAD and TOI answers, so it tests only the new lookups.
The arm B rule is new and untested on real DR4 data. The DR4 column names are unknown until
release, which is why the gate exists. A positive control proves a lookup works at the moment it
runs, not for every later star; a mirror that fails mid-run gives "unknown" for that star.
